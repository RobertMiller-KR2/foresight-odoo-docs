Routes, warehouse settings and recovery

Current answers for customer delivery routes, 3PL flags, packing lists, deleted pick tickets, Program files and chatter placement.

Sales-order route choices

Choose customer fulfillment routes on quotation and sales-order lines. Warehouse-to-customer delivery routes can use one, two or three steps. Direct vendor-to-customer dropshipping is also allowed. A different source warehouse can be selected when its customer-delivery route is configured.

The .16 filter checks active sales routes and an active rule in the order’s company. The same rule must end at a customer and start at a warehouse internal location or a vendor. Receipt-only and internal resupply routes do not qualify. Existing selected routes are preserved.

Availability on 22 October: Warehouse Transfers .16 is sandbox-tested and prepared for production. Production is still .15; do not assume its dropdown is filtered. A manual’s version is not a deployment confirmation.

For warehouse-to-warehouse stock movement, use Warehouse Transfers and the existing resupply route.

Outside warehouse and Managed by a 3PL

SettingMeaning and effect
Outside Warehouse for ShipmentsDesignates an external warehouse. It can qualify customer deliveries for 3PL packing-list PDFs. The current transfer builder can use any two same-company warehouses with a valid existing resupply route.
Managed by a 3PLWhen this warehouse is the source of a Warehouse Transfer, confirmation uses the BOL/email workflow and separate dispatch confirmation instead of creating an internal source pick ticket. It also qualifies customer deliveries for 3PL packing-list PDFs.

An external fulfillment provider normally uses both settings. Neither setting creates warehouses, routes or inventory. Confirm the dispatch contact and shipping addresses before sending instructions. The separate Celestial fulfillment setup is an explicit opt-in and must not be assumed enabled by these flags.

Customer 3PL packing lists

  1. Open the confirmed sales order and select 3PL Packing Lists.
  2. Review the existing noncancelled customer deliveries by warehouse.
  3. Download the separate warehouse PDFs and verify the customer consignee, shipping warehouse, products and quantities.

Each delivery retains its own packing-list reference and pages. The button prepares documents; it does not allocate stock, split deliveries, validate shipments or send provider email. Full invoice and delivery address blocks on the order form are a separate display feature and do not change printed report layouts.

Recover a deleted pick ticket

If only a PDF or paper copy was lost, open the existing transfer and print it again. No stock record needs recreating.

If the actual transfer record was deleted, ask an Inventory administrator to inspect the original sales order, all related transfers, stock moves, quantities already delivered, reservations and any location-level child tickets. Check every status, including cancelled transfers. Do not duplicate the order or assume a zero Delivered value proves that every earlier operation is absent.

For a confirmed sales-order line whose transfers and moves are entirely missing and with no completed work to preserve, an administrator can retrigger Odoo’s native procurement for the missing requirement. In the verified recovery, the line was saved temporarily at zero, then restored to its exact original quantity and saved again. The order stayed confirmed and retained its original date, pricing and customer. This is an administrator recovery step, not a routine picking procedure or a restore button.

After recovery, verify exactly the intended demand, source/destination, company, order link and stock reservations. A recreated ticket gets a new transfer number. Leave it unvalidated until the goods have physically moved. If any existing or completed moves, partials, child tickets, purchases or other downstream documents remain, reconcile those first and use a targeted repair rather than the zero-and-restore procedure.

This sales-order recovery does not apply to the Warehouse Transfers builder: confirming an already confirmed load is a safe retry and does not rebuild deleted transfers. Escalate a deleted load operation for inspection.

Program files and Event Week

Production Program Builder .52 supports entering Event Week manually, including without an Event Date. Review both values when supplied.

The Store Program Excel importer in .54 is currently sandbox-only and excluded from the prepared production update. It imports supported store-item workbook rows in Program Builder; product matches are required before quote generation. It is not an unrestricted generic-file importer. The PO Import Wizard is a separate tool for QuickBooks purchase-order PDFs.

Move chatter back to the side

Widen or maximize the browser, or reduce browser zoom to provide enough horizontal room for Odoo’s side chatter layout. When the chatter is on the side, drag its divider to adjust width. The Chatter Resize module has no documented side/bottom toggle; narrow windows can place chatter below the form.

Source versions and tonight’s preparation

Production source is main; sandbox source is sandbox. The version register distinguishes documented features from each environment’s source pin. Check Odoo Apps for actual installed versions before using a feature.

All 41 sandbox addons are linked to separate repositories. Production currently has 39 repository links plus two embedded addons; the prepared update converts Celestial Fulfillment and Sales Order Full Addresses to byte-identical standalone repositories and upgrades Warehouse Transfers to .16. Separate repositories do not remove module dependencies.

The existing 7:00 PM America/Chicago schedule prepares and tests updates. It does not authorize automatic production deployment. The prepared .16 candidate passed 173 native tests with no failures or errors; this is scoped acceptance, not a pass for every unrelated addon.

Before a separately approved production deployment, recheck the exact candidate, installed versions and current main, then verify a fresh completed database and filestore backup with matching rollback source. Never copy sandbox business records, credentials or test configuration into production.
